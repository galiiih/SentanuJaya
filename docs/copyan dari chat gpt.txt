==================================================

JANGAN menggunakan:

DELIVERED sebagai database default.

JANGAN membuat:

status = DELIVERED

ketika Surat Jalan baru dibuat.

Required lifecycle:

DRAFT
  ↓
READY
  ↓
DELIVERED
  ↓
ACCEPTANCE_PENDING
  ↓
PARTIALLY_ACCEPTED
  ↓
ACCEPTED
  ↓
INVOICED

Cancellation:

DRAFT → CANCELLED
READY → CANCELLED

Jika existing schema menggunakan enum/status yang lebih sederhana, jangan langsung mengganti atau menghapus nilai existing tanpa migration compatibility strategy.

Audit existing implementation terlebih dahulu.

Pastikan default status untuk create Surat Jalan adalah:

DRAFT

Bukan DELIVERED.

==================================================
INVOICE
==================================================

LOCKED:

N SJ → 1 Invoice.

Invoice boleh menggabungkan beberapa SJ.

Pastikan:

- semua SJ dalam invoice berasal dari customer yang sama
- SJ valid untuk invoice
- hanya quantity accepted OK yang invoiceable
- rejected quantity tidak invoiceable
- unaccepted quantity tidak invoiceable
- delivered-only quantity tidak invoiceable
- previously invoiced quantity tidak boleh ditagihkan ulang
- concurrency protection mencegah double invoicing

Jangan mengubah architecture invoice_delivery_links tanpa alasan kuat.

==================================================
CUSTODY
==================================================

Surat Jalan DELIVERED harus menjadi trigger untuk custody outbound jika line tersebut merepresentasikan customer-owned goods.

Pada DELIVERED:

1. lock custody balance
2. validate available balance
3. reject jika quantity > balance
4. create OUT_TO_CUSTOMER
5. reduce balance
6. update SJ status
7. audit
8. commit atomic

Jika gagal:

ROLLBACK seluruh transaction.

Tidak boleh negative custody balance.

==================================================
ACCEPTANCE
==================================================

Acceptance harus mendukung multiple records.

Contoh:

Delivered = 10

Acceptance 1:
OK = 6
Reject = 2

Acceptance 2:
OK = 2
Reject = 0

Final:

OK = 8
Reject = 2

Validation:

SUM(OK) + SUM(REJECT) <= delivered

Revenue eligible:

SUM(OK) - previously_invoiced

Reject tidak pernah revenue.
